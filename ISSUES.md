# Issues

## Open
- [ ] **Search results link to the account page, not the specific post** — `templates/stages/browse.html:58` builds `href="/account/" + r.platform + "/" + r.account"`, dropping the `r.post_id` that's already available in the search result. The roadmap explicitly calls for results to "link to the post in the account view." Fix: add a `#post-<id>` fragment to the link and a matching `id="post-<id>"` on each post `<div>` in `templates/account.html` (currently only `data-post-id` is set at `templates/account.html:211`).
- [ ] **`account.html` renders Twitter-only metric field names for every platform** — `templates/account.html:234-236` and `:333-335` read `post.metrics.likes` / `.retweets` / `.replies`, but `Item.metrics` is source-specific (Reddit uses `score`/`num_comments`; the new Mastodon connector uses `favourites`/`reblogs`/`replies` per `connectors/mastodon.py`). Non-Twitter posts silently show 0 for all three. Fix: map each source's actual metric keys (or fall back gracefully) instead of assuming Twitter's names.
- [ ] **Configure stage's source dropdown is a hardcoded list that's missing the Mastodon and Bluesky connectors** — `static/js/configure.js:6` literally lists `['facebook', 'reddit', 'rss', 'twitter', 'youtube_community']` instead of reading from `core/registry.py`'s `available_sources()` (already exposed dynamically to Connect via `/api/config/sources`'s `available` field, per `static/js/connect.js:36`). Since `mastodon` and `bluesky` were added to the registry (`core/registry.py`) but never added here, there's no way to add a Mastodon or Bluesky crawl target from the Configure UI. Fix: source this list from the same `available` data Connect already uses, or add an equivalent server-side endpoint.
- [ ] **Connect stage has no hint/secret metadata for the Mastodon and Bluesky connectors** — `static/js/connect.js`'s `HINTS` (line 3-9) and `SECRETS` (line 12-15) objects list one entry per existing source (`youtube_community`, `reddit`, `rss`, `twitter`, `facebook`) but have no entries for `mastodon` or `bluesky`, so those sources show a blank hint and never mask their `token`/`app_password` fields as secrets on that stage. Fix: add `mastodon: '...'`/`bluesky: '...'` hints and mark their token/password fields as secrets, matching the pattern used for `facebook`'s `graph_token`.
- [ ] **Storage stage's Azure field label breaks the "`<Provider> <field>`" naming pattern used for S3/GCS** — `templates/stages/storage.html:51` and `:72` label the bucket field `S3 bucket` and `GCS bucket` respectively, but the equivalent Azure field at `templates/stages/storage.html:88` is just labelled `Container`, with no `Azure` prefix. Fix: rename it to `Azure container` to match the other two backends.
